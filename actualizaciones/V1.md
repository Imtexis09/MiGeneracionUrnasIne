# Plan de Actualización — Mi Generación en las Urnas (V1)

**Fecha:** 05-oct-2026
**Objetivo:** Dejar la aplicación profesional y presentable, corregir errores y asegurar datos reales del INE.

## Diagnóstico

- `public/data/cohorts.json` es MOCK (CDMX, 3 cohortes, valores inventados); el pipeline genera `data/participacion_edad.json` con esquema distinto al que espera el frontend.
- KPI cards hardcodeados en `App.svelte` (52.4%, 47.6%, 54.1%, "+3% vs 2018").
- `role="table"` redundante, exports muertos, warnings de build.
- Filtros y botones sociales decorativos (sin funcionalidad).
- Documentación inconsistente: `INSTALACION.md`, `LEEME.md` (rutas inexistentes `codigo/`, `datos/`), `README.md` con headers rotos.
- Falta `pipeline/requirements.txt` y tests implementados.

## Plan por fases (priorizado)

### Fase 3 — Actualización masiva profesional del Frontend (PRIORIDAD)
8. Rediseño visual profundo alineado a `Especificaciones Frontend.md`: paleta, gradientes, espaciados consistentes, micro-interacciones (hover, focus, loaders), estados de UI (vacío, carga, error, sin-datos), hero/KPIs/dashboard/impacto con jerarquía profesional.
9. Layout y responsive: grid, sticky sidebar, tipografía fluida (`clamp`), mobile-first.
10. Accesibilidad: skip link, `aria-live` en resultados, navegación por teclado verificada, contraste AA.
11. Pulido UX: disclaimers de pseudo-cohorte, mensajes neutros, tooltips y leyendas en D3/Canvas.

### Fase 2 — Corrección de errores funcionales
4. KPI cards calculados con datos reales desde `cohortData`.
5. Eliminar `role="table"`, exports muertos y warnings de build.
6. Hacer funcionales o eliminar filtros/botones decorativos.
7. Verificar que `Comparacion`, `SillaVacia`, `Tarjeta` consuman datos reales.

### Fase 1 — Integración de datos reales (Backend/Pipeline)
1. Crear/ajustar script (`pipeline/cohorts_builder.py` o extender `pipeline.py`) que transforme `data/participacion_edad.json` → `public/data/cohorts.json` (cohortes de 3 años × entidad × tipo de elección, `participacion_pct`, `lista_nominal`, edad en la elección).
2. Regenerar `public/data/cohorts.json` con los 6 ZIPs de `data/raw/`.
3. Agregar `pipeline/requirements.txt` y actualizar `INSTALACION.md`/`LEEME.md`.

### Fase 5 — Verificación de build
15. `npm run build` limpio sin warnings, `dist/` < 1 MB, `npm run preview` funcional, pipeline Python reproducible.

### Fase 6 — Pruebas de escritorio (QA manual)
16. Pruebas funcionales del flujo completo (selector → KPIs → gráfica → comparación → silla vacía → tarjeta PNG), casos borde (años límite, entidad sin datos → fallback nacional).
17. Pruebas de UI/UX en 1366×768, 1440×900 y 1920×1080.
18. Pruebas de accesibilidad en escritorio: teclado, zoom 150–200%, contraste, `prefers-reduced-motion`.
19. Validación de datos: valores mostrados vs `data/participacion_edad.json` y `reporte_validacion.md`.
20. Registro de resultados en `Historial/PRUEBAS_ESCRITORIO.md` con capturas y bugs corregidos.

### Fase 4 — Documentación y entrega profesional
12. Reescribir `README.md` limpio con capturas y pasos reproducibles.
13. Coherencia entre `METODOLOGIA.md`, `LICENCIAS.md`, `INSTALACION.md`, `LEEME.md`.
14. Organizar `Historial/` y actualizar `CHECKLIST_ENTREGA.md`.
